# CLAUDE.md — веб-приложение «Подбор реабилитационной программы»

Этот файл читает Claude Code при работе в репозитории. Здесь всё, что нужно знать, чтобы построить и
поддерживать веб-приложение поверх готовой онтологии. **Онтология, правила и запросы уже готовы и проверены — не переписывай их,
а используй.**

## Что строим

Веб-приложение на **FastAPI + Jinja2**: карточки с данными базы знаний и **кнопки, которые вызывают рекомендательные
SPARQL-запросы** (подобрать упражнения, программу, врача/тренера, инвентарь, найти замену, проверить программы).
Весь интерфейс — на русском.

## Онтология — что нужно знать

* Пространство имён: `PREFIX reh: <http://www.semanticweb.org/rehab/ontologies/2026/rehab-program#>`
* Имена классов, свойств и экземпляров — **кириллица в CamelCase**, экземпляры — `Класс_Ключ`
  (`reh:Пациент_Новиков`, `reh:Упр_КошкаКорова`, `reh:Диагноз_Плоскостопие`, `reh:Цель_УменьшениеБолиВСпине`).
* Человекочитаемые подписи: у пациентов/специалистов — `reh:ФИО`, у остальных — `reh:название`
  (у противопоказаний, показаний, эффектов, техник — `reh:описание`).
* Ключевые классы: `Пациент`, `ДанныеПациента`, `Диагноз`, `РеабилитационнаяПрограмма`, `Упражнение`, `Показание`,
  `Противопоказание`, `ЦельРеабилитации` (подклассы `УменьшениеБоли`, `ВосстановлениеПослеТравмы`,
  `ПрофилактикаХроническихЗаболеваний`), `КлиническоеИспытание`, `Специалист` (`Тренер`, `Реабилитолог`),
  `СпортивныйИнвентарь`, `Производитель`.
* Путь «пациент → диагноз»: `?p reh:имеетДанные/reh:содержитДиагноз ?диагноз`.
* Полное описание с таблицами — `docs/MODEL.md`. Данные: 11 пациентов (4 без программы), 8 диагнозов, 5 специалистов,
  15 упражнений, 7 программ, 7 испытаний, 10 единиц инвентаря.

## Загрузка графа и правил (делать ОДИН раз при старте приложения)

```python
from rdflib import Graph
NS = "http://www.semanticweb.org/rehab/ontologies/2026/rehab-program#"
g = Graph(); g.parse("ontology/rehab_program.owl", format="xml")
rules = open("rules/materialize_rules.ru", encoding="utf-8").read()
before = -1
while len(g) != before:              # 2–3 прохода до неподвижной точки
    before = len(g)
    g.update(rules, initNs={"reh": NS, "xsd": "http://www.w3.org/2001/XMLSchema#"})   # initNs ОБЯЗАТЕЛЕН
```

* `initNs` обязателен: rdflib не переносит `PREFIX` на операции после `;` в UPDATE-запросе.
* После правил в графе появляются выведенные факты: классы `ПациентСОжирением`, `ПациентСИзбыточнымВесом`,
  `ПожилойПациент`, `ОптимальноеУпражнение`, `ЭффективноеУпражнение`, `БезопасноеУпражнение`,
  `УпражнениеСОсторожностью`, `ПрограммаСРиском`, `БюджетныйИнвентарь`, `ОпытныйСпециалист`; свойства
  `имеетДиагноз`, `подходитУпражнение`, `неРекомендуетсяУпражнение`, `рекомендуемыйСпециалист`, `рекомендуемаяЦель`,
  `нуженИнвентарь`, `весПриИМТ25`, `весПриИМТ30`. Показывай их **бейджами** на карточках («Ожирение», «Пожилой»,
  «Оптимальное», «Программа с риском», «Бюджетный», «Опытный»).
* **Никогда не сохраняй граф обратно в .owl** — выводы живут только в памяти.
* Граф читается только на чтение → держи один экземпляр в модуле, обращения потокобезопасны. Если очень хочется — `threading.Lock`.

## Формат файлов запросов `queries/recommend/NN_id.rq`

Заголовок — строки `# ключ: значение` до первой строки без `#`:

```
# id: exercises_for_patient                       ← идентификатор для API
# title: Упражнения для пациента                  ← заголовок карточки результата
# button: Подобрать упражнения                    ← текст кнопки
# description: …                                  ← подсказка под кнопкой / над результатом
# param: пациент | individual:Пациент | reh:Пациент_Новиков     ← имя | тип | значение по умолчанию
# param: бюджет | number | 5000
# card: title=упражнение; score=рейтинг; warn=…; tag=…; fields=почему,сложность,…   ← как рисовать карточку
```

* Типы параметров: `individual:<Класс>` — выпадающий список экземпляров этого класса (подпись — `ФИО`/`название`,
  значение — локальное имя, например `Пациент_Новиков`); `number` — числовое поле.
* Подстановка: в тексте есть строки `VALUES ?x { reh:Пациент_Новиков }   # PARAM пациент`. Заменяется содержимое `{ … }`
  в строках с маркером `# PARAM <имя>`. Значение по умолчанию уже стоит — поэтому тот же файл без изменений работает в Protégé.
* **Безопасность:** имя экземпляра проверяй регуляркой `^[0-9A-Za-zА-Яа-яЁё_]+$` и что такой экземпляр нужного класса
  существует; число — через `float()`. Никогда не вставляй в запрос сырую строку пользователя.
* `card: boolean` и текст, начинающийся с `ASK`, — запрос возвращает `true/false` (`res.askAnswer`).
* Готовые функции `parse_query_file`, `bind_params`, `param_value`, `run_query`, `to_py` — в `scripts/check_queries.py`.
  Перенеси их в `app/sparql.py` (или импортируй) — не изобретай заново.
* Колонки, совпадающие с IRI (`?у`, `?пр`, `?с`, `?инв`, `?зам`, `?пац`, `?другой`), — служебные: используй как ключ/ссылку,
  на карточке не показывай.
* Порядок значений внутри `GROUP_CONCAT` не гарантирован — это нормально.

### API (JSON)

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/stats` | счётчики: пациенты, без программы, программы, программы с риском, упражнения, специалисты, инвентарь |
| GET | `/api/options/{класс}` | `[{id, label}]` экземпляры класса для выпадающих списков (Пациент, Диагноз, ЦельРеабилитации, Упражнение) |
| GET | `/api/patients` | карточки пациентов: ФИО, возраст, ИМТ, диагноз, программа (или «нет»), бейджи из правил |
| GET | `/api/patients/{id}` | профиль пациента + его программа с упражнениями |
| GET | `/api/catalog/{exercises|specialists|equipment|programs}` | справочники для карточек |
| GET | `/api/queries` | список запросов: id, title, button, description, params (+ варианты), card |
| POST | `/api/recommend/{query_id}` | тело `{"params": {"пациент": "Пациент_Новиков"}}` → `{columns, rows}` или `{answer}`; 404 — нет запроса, 422 — плохой параметр |

### Страницы (HTML)

1. **Главная `/`** — шапка-градиент с названием, ряд **карточек-счётчиков** (`/api/stats`), сетка **карточек-кнопок**
   для 12 запросов (иконка, заголовок, описание, кнопка). Акцентная карточка — «Кому нужна программа».
2. **Пациенты `/patients`** — карточки пациентов с бейджами; клик → страница пациента.
3. **Пациент `/patients/{id}`** — профиль (возраст, рост/вес, ИМТ, подготовка, диагноз, анамнез) и **панель кнопок**
   всех запросов с параметром `пациент` (01, 03, 04, 05, 06, 08, 09) — пациент подставляется автоматически.
   Результаты появляются ниже **карточками** без перезагрузки страницы (fetch → POST `/api/recommend/...`).
4. **Рекомендации `/recommend`** — выбор запроса + форма параметров, построенная по метаданным (`select` для individual,
   `input type=number` для number) + кнопка + результат карточками и переключатель «Таблица».
5. **Каталог `/catalog`** — вкладки Упражнения / Специалисты / Инвентарь / Программы (карточки с бейджами из правил).

### Как рисовать карточку результата

Из поля `card` метаданных: `title=` — заголовок; `score=` — крупное число/полоска (рейтинги 0–100 — полоса заполнения,
`совпадение`/`похожесть` — звёзды или «3 из 3»); `warn=` — красная плашка, если значение непустое и не `0`;
`tag=` — бейдж; `fields=` — список «подпись: значение». Подпись поля — имя колонки, разбитое по заглавным буквам
(`средняяЭффективность` → «Средняя эффективность»). Числа: дробные — 1 знак после запятой, проценты — «%», цена — «₽».
Пустой результат — дружелюбный текст («Для этого пациента подходящего инвентаря не требуется — упражнения без снаряжения»),
а не пустая сетка. ASK → большая зелёная «Можно» / красная «Нельзя».

## Подводные камни

* rdflib: доступ к колонке — `row["упражнение"]` (кириллица работает); Decimal → `float`; `xsd:boolean` → `bool`;
  ячейка может быть `None` (OPTIONAL) — показывай «—».
* Не используй в `.rq` функции `YEAR()`, `NOW()`, `CONTAINS()`, `STRSTARTS()`, `ROUND()`, `CONCAT()`, `LCASE()` —
  в Protégé (Sesame 2.7) они дают «Unknown function», а файлы должны работать и там. Форматирование — в Python.
* Новые запросы добавляй файлом в `queries/recommend/` с тем же заголовком — они появятся в интерфейсе автоматически.
* Если меняешь данные: правка в `scripts/build_ontology.py` → `python3 scripts/build_ontology.py` →
  `python3 scripts/check_queries.py --write` (обновит эталоны).
